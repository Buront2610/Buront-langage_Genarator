## 15. 着手順と完了の運用

最初は次の順に進める。

1. **M0-01 → M0-02:** 作業中変更を含む基準と、設計の反例を固定する。
2. **M0-03 → M0-04:** 候補の状態・採用・表示を揃え、既知の意味破損を合格させない。
3. **M0-05 / M0-06 / M0-07 / M0-08:** 辞書・要求上限、古い応答、配信境界、資産識別を修正し、M0を閉じる。
4. **M1-01 → M1-02 → M1-03 → M1-04 → M1-05 → M1-06 → M1-07 → M1-08 → M1-09 → M1-10:** 最小創作経路と人手比較を完成させる。
5. M2以降は各段階の受入を確認して進む。M5の比較待ちだけを理由に標準経路のM6を止めない。

各タスクの状態は `未着手 → 実装中 → 検証待ち → 完了` とし、完了時に変更差分・試験結果・使用した資産版・残る限界を記録する。依存未解決は具体的な依存IDまたは判断項目を記す。人手評価が必要なタスクを、自動テストだけで完了にしない。

この表は全47タスク。実装済みの機能は、該当する新契約の完了条件を確認してから完了へ更新する。
