# ブロント語変換機

通常の日本語から複数のブロント語候補を作り、実ログとの文章比較と検証を通して採用文を選ぶローカルWebアプリです。LLMは使用しません。入力した文章は外部へ送信しません。

## 起動方法

Windowsでは `start.bat` をダブルクリックしてください。ブラウザで `http://127.0.0.1:4173` が開きます。

コマンドから起動する場合:

```powershell
npm start
```

全文コーパスを利用するため、`index.html` の直接起動ではなくローカルサーバーから起動してください。

現在の生成済みデータには次が含まれます。

- 2,452件の構造化投稿
- 投稿から分割した9,591文
- 手元ログと一致した2,379投稿
- ログ倉庫から補完した73投稿
- 5段階の文章改変差分
- 名言集の見出し165件、強調語録839件を原ログ152投稿へ接続し、文脈を確認できた51種の使用条件つき会話・展開パターン
- 原文寄りモード用の36機能別構文、35役割。全36構文を実ログまたは名言集の観測語へ接続し、起動時に根拠欠落を検査
- 原ログの数値アンカー979件を10種の構文へ分類したアンカー構文台帳
- 改変集23話、135,114文字から作った長文用統計モデル

改変集の本文は保存せず、文長、接続、断定、反復、会話率、n-gramなどの統計だけを保持しています。

## 変換の流れ

画面の「文章の組み替え」では二つのモードを選べます。

- `原文寄り`: 文ごとの事実関係を保ち、入力を状態、評価、危機、未来、達成、対抗、感謝、賛同、証拠、中立観察へ分類する。ひとつの案に語録を機械的に積み重ねず、尺度比較、一般人への影響、準備自慢など機能の異なる構文を別々の3案として返す
- `完全ブロントナイズ`: 段落全体を一単位にし、本人の自慢、知り合いのナイトの武勇伝、第三者の目撃談、結果先行の回想、LSの噂話へ構造から再編する

さらに「ログ倉庫の系列」で、検索・文体採点・表記・系列構文を同時に切り替えられます。区分は年から独自に推定せず、ログ倉庫の[ログ索引](https://kenkyonanight.xxxxxxxx.jp/log.html)にある「適当に系列別に分けました」という9分類を正本にします。

- `ロト時代＋暗黒騎士系`: 1,023投稿
- `グラットンスレ系`: 395投稿
- `最高の騎士系`: 132投稿
- `名無し系（2003～2004）`: 108投稿
- `鯖スレ系`: 89投稿
- `ネガ侍系`: 236投稿
- `謙虚な騎士系`: 247投稿
- `ギルティギア系`: 34投稿
- `その他`: 115投稿

系列ページ本文と構造化投稿を照合し、2,379投稿を分類しています。`all.html` 由来でも各系列ページに掲載されていない補完73投稿は推測で割り振らず、`全系列` でだけ使用します。各系列では検索対象、n-gram、特徴量、半角表記対応を別々に作り、系列ページ内で根拠を確認した3種類、合計27種類の談話構文を使います。一度の変換では3案すべてが別の系列構文になります。原文寄り・完全ブロントナイズの両方へ適用され、比較欄の参照ログも指定系列だけに限定されます。出現回数は分析に使いますが、候補の抽選重みには使いません。

完全モードはまず入力を救援、単純達成、未来予定、未解決の危機、対抗、状態描写、評価、中立観察、理解と感謝、賛同、証拠提示へ分けます。救援・達成では危機、介入、成果、反応、結論を、未来予定では準備、未完了の確認、結論を、未解決の危機では現状、危険、未決着の確認、結論を検証します。状態描写では観察、一般人との対比、耐性の自慢、結論を、中立観察と評価では認識差、見切り、反応、結論を別々に検証します。順序は固定せず、悲嘆からの逆転、証拠先出し、予知、反論、警告、後日談先行などへ再配置します。ただし、対抗者、情報源、賛同先、証拠元、期限、欠損、危険、後発問題などの入力条件が一致する段落経路だけを使います。名言集由来の展開型が最低3種、異なる展開機能が最低3種含まれること、必要なアンカー構文があること、同じ事実が重複しないことも検証します。数値、否定、URLなどの保持に加え、予定や未解決事実を完了扱いしていないかも検証します。

未来予定と未解決の文に系列モードを重ねた場合も、各系列の3構文は維持します。ただし「これで勝つる」「きょうきょ完了」など結果確定後の原型は、同じ系列の根拠語を残した準備・未決着形へ時制適応し、完了したという主張にはしません。

対抗文の「なんだ急に牙抜いてきた」は `>>○○` までを一体として生成します。入力済みの数値・文字アンカーは保持します。アンカーがなければ原文から挑戦者、批判者、発言者の名詞句を抽出するため、「営業部の田中」が挑んだ文では `>>営業部の田中` になります。原文中のかな語を数字の読みに変換できた場合は語呂候補にもできます。相手を特定できない文ではこの語録を使わず、無関係な役職や乱数番号を足しません。

アンカーは単なる宛先置換ではありません。単独返信、節先頭、並列評価、対象評価、文中引数、証拠元、賛同先、文末参照、呼びかけ、`>>対象感謝` の融合遂行の10構文を別々に扱います。たとえば `>>対象感謝` は「新しく理解した」と「その情報源を特定できる」が揃う場合だけ使い、一般的な成功や無関係な登場人物には付けません。

1. 入力を文単位へ分割する
2. 内容語と文章の意図を抽出する
3. 内容語と文字断片のTF-IDF疎ベクトルを作り、9,591文からコサイン類似度の高い実ログを検索する
4. 段階的な比較資料を使い、語彙、表記、構造、論理展開の候補を複数作る
5. 短い入力では実ログで存在を確認できた文末型と意味別スロットを、出現数に関係なく均等なシャッフル袋で組み替える
6. 候補ごとに意味保持とブロント語らしさを別々に採点する
7. 基準を満たした候補から、直近8回と名言群・段落構造が最も重ならない集合を作り、その中から均等に抽選する。実ログ参照も最高点一点へ固定せず、近い上位帯から一様抽選し、相互コサインが高すぎる参照を減点する
8. 基準未達なら保守的な候補を作り直して再検証する

実ログでは文末の句点が少ないため、変換結果へ「。」を機械的に補いません。複数文は実ログに近い改行区切りで出力します。

画面では、その変換時に生成されて検証を通過した3案を常時表示します。原文寄りモードでは、同じ語録を重ねた言い換えではなく、入力の出来事型に適合する異なる機能構文を優先します。同じ入力でも採用案は変化し、利用可能な構文を一巡するまで直近と同じ構文を避けます。各入力文と採用文の差分、採点内訳、構文の機能、参照した実ログ、比較した候補も確認できます。

詳しい生成・比較手順は [docs/algorithm.md](docs/algorithm.md)、モジュール境界とアンカー構文の拡張方針は [docs/architecture.md](docs/architecture.md) を参照してください。

## 検証項目

- 数値、URL、メールアドレス、英字識別子の保持
- 内容語の保持率
- 肯定と否定の一致
- 実ログのn-gramモデルとの近さ
- 入力と参照ログのTF-IDFコサイン類似度
- 長文改変モデルとの近さ
- 表記、接続、断定、誇張など複数の文体次元
- 括弧、反復、語尾接続の破綻
- 名言集由来の展開型数と、入力事実の重複使用
- イベント型に必要なアンカー構文と、参照対象の役割一致
- 原文寄りモードの機能構文、出来事型との適合、同一案内での機械的な語録重複
- 原文寄り構文と実ログ・名言集の根拠語との接続
- 指定した倉庫系列と参照投稿ID、系列構文、系列別n-gramの一致
- 生成文と9系列それぞれのTF-IDF重心・実ログ近傍とのコサイン比較

テストは生成器自身が作った候補を生成器自身で正解扱いするだけではありません。実装から独立した固定オラクルを用意し、倉庫9系列の正例を検証します。同時に、別系列の構文、入力にない否定、出来事型違いの語録、数値欠落という改変候補が確実に不合格になることも確認します。短文と長文の両方で、各系列が異なる3案を返し、参照投稿がその系列ページの投稿ID集合に属することと、入力中の値を保持することも検査します。さらに、同じseedで文章・参照・コサイン値が再現すること、30種類のseedで出力と参照が一候補へ集中しないこと、生成文を全9系列のベクトルと比較した順位も検査します。

## テスト

Node.js 18以上で実行できます。通常の実行とテストに外部パッケージは不要です。

```powershell
npm test
```

## コーパスの再構築

手元ログとログ倉庫を再照合する場合:

```powershell
npm run build:corpus
```

別のログを使う場合はパスを引数に渡せます。

```powershell
node scripts/prepare-corpora.js "C:\path\to\burontlog.txt"
```

改変集の統計を再構築する開発用スクリプトは `scripts/analyze-novel.js` です。これは本文をブラウザで取得して統計化する工程だけPlaywrightを使用します。生成後の変換器はPlaywrightを必要としません。

名言集を再取得して分類する場合:

```powershell
npm run build:quotes
```

## ファイル構成

- `lib/corpus-engine.js`: 検索、候補生成、比較、検証
- `lib/text-analysis.js`: 文分割、特徴抽出、n-gram
- `lib/vector-space.js`: TF-IDF疎ベクトル、転置索引、コサイン検索、系列重心・近傍分類
- `lib/quote-grammar.js`: 名言集由来の展開型と反復検出
- `lib/grammar/context-model.js`: 入力事実、出来事型、参照対象の役割抽出
- `lib/grammar/anchor-grammar.js`: 10種のアンカー構文の条件判定、対象選択、表層化
- `lib/grammar/anchor-frames.js`: 感謝、賛同、証拠提示を段落へ組み込む構成器
- `lib/grammar/observation-frames.js`: 中立観察と評価を観察自慢へ再構成する専用構成器
- `lib/grammar/faithful-quote-grammar.js`: 原文寄りモード用の機能別構文、使用条件、検出
- `lib/era-profiles.js`: 倉庫9系列の部分コーパス、特徴量、n-gram、表記対応
- `lib/grammar/era-grammar.js`: 系列ごとの談話構文、検出、系列内根拠照合
- `lib/grammar/phrase-constructions.js`: 原ログで観測した構文台帳
- `lib/grammar/random-utils.js`: 重みづけしない抽選とシャッフル
- `data/log-corpus.json`: 構造化した実ログ
- `data/quote-corpus.json`: 名言集の見出し、強調語録、分類
- `data/style-model.json`: 実ログと段階比較から作った文体モデル
- `data/novel-model.json`: 長文改変の統計モデル
- `data/archive-series.json`: 倉庫9系列の出典URL、本文一致投稿ID、取得元ハッシュ
- `app.js`: 画面操作と比較結果の表示
- `server.js`: ローカルAPIと静的ファイル配信
- `test/`: コーパス、意味保持、変換、独立オラクル、負例検証の自動テスト
