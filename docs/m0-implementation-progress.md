日付: 2026-09-21。対象は基準固定、候補契約、入力の保護、旧画面の要求整合。

## 実装した内容

- 候補の `passed / needs_review / rejected` を選択経路と診断表示へ通し、合格集合が空のときに不合格候補へ戻る処理を除いた。必須failをunknownや品質点で相殺しない。
- APIの候補に安定したID、検証状態、候補ごとの比較・要約を付け、`selectedCandidateId` で採用を明示した。0/1/2案を許容し、ゼロ案は元の空白を含む原文、`fallback`、`shortfallReason` を返す。原文と句読点だけが違う結果も成功候補には数えない。
- 画面で候補を選択すると本文・差分・参考点・検証・根拠を同じIDで切り替える。不合格・要確認は比較詳細で区別する。原文保持を合格と表示せず、未評価の点はゼロではなく「未評価」と表示する。
- 数量の表記全体・符号・単位・出現数、URL・メール・英字識別子・明示アンカーを照合する。`100円` が `1100円` の一部に残っただけでは保持としない。数量の全角表記はNFKCで対応するが、URL等は原値を照合する。
- 一文字の入力を捨てず、入力の行頭アンカーを保持する。アンカー清掃はコーパス構築時だけ明示指定する。一文字の項候補の欠落を、他の内容語の高得点で補償しない暫定ガードを追加した。
- 原文を入口でtrimせず、入力型・空白のみ・孤立サロゲートを検査し、5,000文字制限と画面の文字数をUnicode scalar単位に揃えた。内部の保護値位置はまだUTF-16であり、M1の共有span契約の実装完了ではない。
- 再検証用の保守的候補を元入力から作るようにした。長文の文ごとの言い換えにも要求のseedから作った乱数を渡す。
- 旧画面にrevision・要求スナップショット・共通実行ガードを追加した。入力、設定、辞書、消去で通信を取り消し、古い応答・catch・finallyが新しい実行を変更しない。

### 未対応の意味検証

監査の10反例のうち、次の5件は原文寄りの検証でまだpassedになる。監査コマンドはこの状態を終了コード1として返す。完全モードでrejectedになっていても、語録数等の別条件による拒否の可能性があり、意味解析の完成とは数えない。

| ID | 未対応内容 |
|---|---|
| T-02-role | 同じ数量集合でfrom/toを逆転させる |
| T-03-roles | 助けた人物と助けられた人物を交換する |
| T-04-scope | 人物ごとの承認・未承認を交換する |
| T-07-mixed | 成果・未解決・予定を混ぜて完了扱いする |
| T-08-attribution | 人の発言内容を確認済みの地の文へ格上げする |

これらは通常回帰テストの成功件数へ含めない。`implemented: false` としてfixtureに残し、実装時に通常回帰へ昇格させる。現行の「passed」は実施した規則検査の通過であり、設計21章の全検査や意味全体の保証ではない。
