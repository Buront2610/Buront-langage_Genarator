## 「んだが。」が生まれる具体的な原因

文字列「んだが」の全出現199箇所について、その直後を数えた。

| 直後 | 原文 | 生成標本 |
|---|---:|---:|
| 本文がそのまま続く | 113 | 0 |
| 改行 | 41 | 0 |
| 疑問符・感嘆符 | 31 | 0 |
| 読点 | 6 | 0 |
| 投稿末尾 | 6 | 0 |
| 句点「。」 | 2 | 25 |

これは形態素による語尾分類ではなく文字列の集計であり、「死んだが」のような用例も含む。それでも、生成がすべて同じ「んだが。」に寄っている事実は明確。

原文12992行では「遅れてしまったんだが」の後に、現場がどういう状態だったかが続く。5729行では「買えたんだが」の後で改行し、武器の評価に続く。そこには後続の内容がある。現在の処理は、入力が持っていた文末を有限規則で置換し、その後の句点をそのまま連結するため、この関係を扱えない。

実装上の該当箇所:

- `packages/core/rewrite-rules.ts`: `ending-*` 規則が末尾を一律に「んだが」「からな」に置換する。
- `packages/core/rewrite-validation.ts`: 変更範囲外の原文をそのまま連結する。
- `packages/core/rewrite.ts`: 語句の変更候補を選び、元の順序で本文を連結する。文体に応じた句読点・改行の構成処理はない。

「からな」も全文検索したが、「わからない」等を含むため、その集計を語尾の使用率とは解釈しない。「ここ大事」は原文にも今回の生成標本にも0件だった。

生成できた32入力について、同じ入力から出た候補を平均し、入力ごとに同じ重みで比較した。

|---|---:|---:|

| 文字種に置換した文字列 | 0.3701 | 0.4735 |

各入力・各生成文について、原文の最近傍と、長さを合わせた最近傍も保存した。完全重複を除いた原文間の高類似ペア6組は別記録に残している。これらは独立した正解ラベルではない。

**以前の監査とはコーパス・特徴数・比較対象が異なるため、数値を直接比較して「前版より良くなった」とは言えない。** 今回の生成標本は保存済み37入力・75出力で、生成処理の7ソースファイルが記録時と一致していることをSHA-256で検査した。未知の入力に対する無作為な性能評価ではない。

PC1と文字数の順位相関は0.913。長さの影響が大きいため、この横軸を「ブロントらしさ」とは解釈できない。文字数・行数・平均行長・最大行長の4特徴を外した29特徴でもPCAを実施し、別図を用意した。比率にも長さの影響は残るので、これで完全に交絡を除去したとはしない。

### クラスタリング

PCAの2次元図ではなく、全標準化特徴でK-meansを実施。K=2〜8、乱数3種類、各10初期値を比較した。平均シルエットが最も高かったK=5について代表投稿を原文で読んだ。

| 群 | 完全重複除外後の件数 | 代表的な傾向 |
|---|---:|---|
| 0 | 240 | 短い疑問・「べ？」型。227件が2002年 |
| 1 | 1,037 | 比較的長い説明・叙述。改行で評価や主張を積み重ねる |
| 2 | 940 | 句点のない短い応答・主張 |
| 3 | 114 | 句点・読点を多く使う文章 |
| 4 | 32 | 数値・空白の多い性能表など |

平均シルエットは0.123と低く、明瞭に分かれた5種類という意味ではない。初期値間のARIは0.994で再現性は高いが、長さ4特徴を外した群とのARIは0.324。前処理の上側クリップを外した場合のARIは0.894。クラスタは作者や真贋のラベルではない。

語彙TF-IDFには別にTruncatedSVDを適用し、同じK=5でも比較した。こちらは「ロト」「侍」「グラットン」等の話題で分かれやすく、文体特徴側の群とのARIは0.184だった。**話題の近さと文体の近さを同じ点数で扱うべきではない。** SVDをPCAとは呼ばない。

## 原文の読み方から実装に戻す事項

1. **入力の文境界をそのまま出力の文境界にしない。** 事実、条件、引用、対比、後続説明、段落を区別して保持する。句点の削除だけで一文につなげる修正は避ける。
2. **「んだが」を断言の万能な変換先にしない。** 後続内容とのつながりを確かめる。原文にも投稿末尾の用例はあるため、単純禁止にもせず、用法を分ける。
3. **短い返答と長い叙述を分ける。** 2002年の短い「べ？」型、改行中心の説明、句点を使う応答、発話を含む長い叙述を一つの語尾置換で処理しない。性能表は散文生成の標準にしない。
4. **引用や疑問符は役割を保持する。** 12994〜12998行のような叙述では、外側の文に句点が少なくても、引用内には感嘆符・読点がある。全記号削除はこの差を壊す。
5. **検証は層を合わせる。** 長さ・応答形式・出典区画を合わせた原文との比較、意味保持、句読点・改行、文のつながりを別々に見る。コサインの上昇だけで合格にしない。
6. **人間評価はユーザーが行う。** 今回は全文解析と原因の特定。生成処理や評価回答には変更を加えていない。
