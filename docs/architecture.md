# 拡張設計

この変換器はLLMを使わず、入力解析、語録文法、候補構成、コーパス比較、検証を分離する。語句の置換だけでなく、入力の出来事型と参照対象の役割を先に決め、条件に合う段落構造だけを生成する。

## 処理境界

1. `text-analysis.js` が文、内容語、数値・識別子を抽出する。
2. `grammar/context-model.js` が事実列、危機、成果、後発問題と、対抗・感謝・賛同・証拠などの出来事型を作る。
3. `grammar/anchor-grammar.js` が入力中の人物・部署を、対抗者、発言者、情報源、賛同先、証拠元へ分類する。
4. `era-profiles.js` がログ倉庫の系列ページごとの部分コーパス、特徴量、n-gram、表記対応を提供する。
5. `quote-grammar.js`、`grammar/anchor-frames.js`、`grammar/observation-frames.js` が完全モードの段落候補を作る。`grammar/faithful-quote-grammar.js` は原文寄りモードで、入力の出来事型に合う機能構文を一案につき一つ適用し、役割の異なる候補を作る。
6. `grammar/era-grammar.js` が指定した倉庫系列の談話構文を外枠として合成し、別系列の混入を検出する。
7. `vector-space.js` がTF-IDF疎ベクトル、転置索引、コサイン検索、系列重心・近傍分類を提供し、`corpus-engine.js` が指定系列の実ログ、段階比較、長文統計と候補を比較する。
8. 意味、否定、保護値、展開段階、語録型、アンカー構文、系列構文、事実重複を検証して採用候補を決める。

原文寄りの33構文は、それぞれ実ログまたは名言集で観測した根拠語を持つ。起動時に全構文の根拠接続を検査し、未接続の構文があれば生成器を開始しない。出現数は使用可否の確認にだけ使い、抽選重みにはしない。

系列構文も同じ根拠台帳を持つ。倉庫の9系列に3構文ずつ置き、各根拠句がその系列ページへ本文一致した投稿に存在するか起動時に検査する。候補選択では内容構文と系列構文を別シグネチャとして扱い、一回の3案でどちらか一方だけが同じになる偏りを避ける。

## アンカーを役割で扱う理由

`>>○○` の後ろに同じ固定文を付ける設計では、対抗者へ感謝したり、証拠元へ挑発したりする。そこで対象は文字列ではなく、値、役割集合、根拠文を持つ。

| 役割 | 抽出根拠 | 使用できる主な構文 |
|---|---|---|
| `opponent` | 勝負、批判、反対、挑発 | 牙、対象評価、呼びかけ |
| `source` | 説明、助言、ログ、記録、証言 | 感謝、証拠元、文中引数 |
| `supporter` | 意見、提案、同意対象 | 賛同、感謝、並列評価 |
| `speaker` | 引用発話 | 単独返信、文中引数、呼びかけ |

入力に明示アンカーがある場合はそれを優先する。自動抽出では役割が一致しない対象へ降格しない。かな語から作る数字の語呂は対抗文だけで候補にし、固定番号表は持たない。

## 構文台帳

`phrase-constructions.js` は原ログ979件の数値アンカーを、単独返信883、節先頭29、並列16、対象評価15、文中引数14、証拠元7、賛同先5、文末参照5、呼びかけ4、融合遂行1へ分類した結果を保持する。出現数は分析結果の表示と整合確認に使い、抽選重みには使わない。

融合遂行 `今回のでそれが良くわかったよ>>対象感謝` は、理解の更新、感謝の意図、特定可能な情報源がすべてある時だけ利用する。観測数が1件なので汎用語尾として拡散させず、専用イベント型として扱う。

## 拡張方法

新しい構文を増やす場合は次の順で行う。

1. 分析スクリプトで原ログ中の用例数と前後文脈を記録する。
2. 構文台帳へ対象役割、必要条件、禁止条件を追加する。
3. `AnchorGrammar.available` と `render` を追加する。
4. 文脈全体を変える必要がある場合だけ専用フレームを追加する。
5. 構文検出を検証器へ追加し、対象なし・役割違いの負例テストも作る。

この境界により、語録追加で入力解析や比較器を直接書き換えずに済み、表層句、使用条件、段落構造、検証規則を個別に変更できる。

## 到達性検証

語録定義が存在するだけでは実装済みとは扱わない。代表文を状態、達成、救援、締切、欠損、危険、対抗、会話、感謝、賛同、証拠、複数参照へ分け、乱数袋を複数巡させる回帰テストで、51展開型と10アンカー構文がすべて実候補へ到達することを確認する。

生成表現の検出規則も同じテスト対象にする。原語の見出しと生成時の活用が違う場合、生成結果を認識できる表現まで明示的に許可する。これにより「生成されたが検証器から見えない」と「定義されたが生成経路がない」を分けて検出する。

原文寄りモードでは、語録数を増やすために前置き、実話注記、疑問形を同じ文へ積まない。状態なら尺度比較、一般人への反実仮想、ナイトの耐性、達成なら予知、格差、謙遜というように、同じ入力事実を別の談話機能へ展開する。画面へ返す3候補は、検証を通過し、構文シグネチャと機能役割が異なるものを先に選ぶ。検証器は内容語、否定、保護値に加え、入力の出来事型と構文の使用条件が一致するかも確認する。

系列モードの回帰テストは実装定義を正解値として読み戻さず、`test/fixtures/era-oracles.json` の固定文、固定件数、固定出典ページを使う。正例に加えて、誤系列、極性反転、出来事型違い、保護値欠落を明示的に不合格とする。さらに短文と長文の生成結果について、各系列3構文の到達、参照投稿IDの所属、数値保持を確認する。
