# 非LLM変換アルゴリズム

## 目的

単語を数個置き換えただけの文ではなく、ブロント語に見られる視点、比較、断定、反応の推測、話の膨張を扱います。同時に、入力に含まれる事実や否定を壊さないことを検証します。

## コーパス層

### 実ログ

ログ倉庫の静的データを投稿単位で読み込み、手元の `burontlog.txt` と本文を照合します。各投稿には板名、スレ名、投稿番号、日時、本文、アンカー先、手元ログ内の存在情報を保持します。

投稿本文は改行と句読点で文へ分割します。各文には内容語、意図分類、投稿元IDを付与します。変換時の検索結果から元投稿へ戻れるため、なぜその文型が候補になったか確認できます。

### 段階的な文章比較

ログ倉庫の比較資料は、同じ内容が5段階で変化します。隣接段階をトークン単位で比較し、次の編集を分離します。

1. 速度や反応の語彙変更
2. 「これは何の話か」という導入
3. 一般人と一級人物の対比
4. 能力の誇張と相手の反応の推測
5. 自己評価、社会的評価、読み手への結論の追加

変換器はこれらを一度に固定適用せず、別候補として生成します。

### 名言集コーパス

ログ倉庫の「名言集っぽいの」をShift_JISの原文から取得し、見出し165件と強調語録839件へ分離します。怒り、悲嘆、警告、勝利、謙遜、証拠、予知、比較、驚き、力、指導、否認へ複数分類し、その分類に出典を持つ使用条件つき文脈適応パターンだけを有効化します。

名言そのものを無条件で貼り付けません。見出しを原ログ152投稿へ逆引きし、元の発話が挑発への返答、期限への警告、失敗後の悲嘆、成功後の謙遜など、どの会話遷移で使われたかを確認します。入力側からも対抗者、会話、期限、欠損、危険、先行する問題、後発問題を抽出し、使用条件が一致したパターンだけを候補にします。たとえば「なんだ急に牙抜いてきた　>>○○」はレスアンカーまでを一体の発話形式として扱い、対抗者が張り合ってきた場合だけ使います。入力にアンカーがあれば数値・文字を問わず保持します。なければ原文の主語、受け身の動作主、引用発言者から相手の名詞句を抽出します。かな語を数字の読みに全て変換できる場合だけ語呂候補を作ります。相手を特定できなければこの展開型自体を無効にし、無関係な役職や乱数番号は生成しません。サーバー障害そのものの描写にも使いません。

入力に実際の危機がない成功談では、周囲が悲しむ展開を捏造せず、一般人と熟練者の力量比較へ切り替えます。「悲嘆から逆転」「証拠を先に提示」「予知から回想」「問題の後日談を先に提示」などの段落経路も、必要な事実役割が入力に存在するときだけ有効になります。

さらに入力全体を救援、単純達成、未解決の危機、対抗、状態描写、評価、中立観察、理解と感謝、賛同、証拠提示へ分類します。寒さなどの状態には尺度、一般人への影響、ナイトの耐性を、中立観察には細部を見切る観察自慢を使い、事件解決の筋を当てません。候補検証も出来事型ごとに切り替えるため、「今日は寒い」から悲嘆や問題解決を作る候補、「カモが泳いでいた」からノーダメージを自慢する候補は採用されません。

### 長文改変モデル

改変集23話は本文を製品へ保存しません。135,114文字から次の統計だけを作ります。

- 文長と段落長の分布
- 会話文と地の文の比率
- 接続語、比較、断定、誇張、括弧表現の密度
- 3文字と4文字のn-gram頻度
- 導入、対比、反応推測、根拠化、現実接続などの構造出現数

### ログ倉庫系列別モデル

分類は投稿日から独自に作らず、ログ倉庫の `log.html` が列挙するロト時代＋暗黒騎士系、グラットンスレ系、最高の騎士系、名無し系、鯖スレ系、ネガ侍系、謙虚な騎士系、ギルティギア系、その他の9系列を使います。

各系列ページをShift_JISで取得し、ページ本文と構造化投稿本文を正規化して完全包含照合します。同じ短文が複数ページにある4件だけはスレ名が載るページで一意化します。2,379投稿が系列ページへ接続し、ページに載っていない補完73投稿は推測で分類せず全系列モードだけに残します。出典URL、取得元ハッシュ、投稿ID集合は `data/archive-series.json` に保存します。

各系列について、検索対象の投稿ID集合、3・4文字n-gram、接続・断定・比較・誇張の特徴量分布、半角表記対応を別々に保持します。系列指定時は、同じ系列内で根拠句を確認できた3種類の談話構文も候補へ付けます。出現率は系列差を説明する観測値であり、抽選確率には変換しません。

## 検索

入力文を `Intl.Segmenter` で内容語へ分割します。内容語は速度、強弱、評価、怒り、勝敗、時間などの概念へも展開します。

内容語とその概念形、内容語内部の3文字断片からTF-IDF疎ベクトルを作ります。TFは対数化し、IDFは全文書頻度から計算します。転置索引で入力とのコサイン類似度が非ゼロの文だけを集め、次の値と組み合わせます。

- TF-IDFコサイン類似度
- 内容語の直接一致
- 同一概念に属する語の一致
- 文章意図の一致
- 文長の近さ
- 手元ログで確認できる投稿への小さな加点

最高点の一文へ固定せず、最高点から16%以内の近傍帯を作り、その中では出現数や得点を確率重みにせず一様に抽選します。二件目以降は、すでに選んだ文とのコサイン類似度を減点するため、同じ投稿だけでなく内容のほぼ同じ参照も並びにくくなります。seed指定時はこの抽選を再現できます。

系列指定時は得点計算の前に投稿ID集合で候補を絞ります。したがって、画面に表示される参照ログも別の系列ページから混ぜません。

## 候補生成

短い入力にも固定の完成文を対応付けません。まず出来事型と参照対象の役割を決め、実ログで確認した発話を、報告、断定、尺度比較、一般人への反実仮想、自慢、警告、挑発への返答、情報源評価などの機能構文として展開します。一案に短句を複数貼るのではなく、機能の異なる候補を別々に生成して3案を返します。出現回数は抽選確率に使わず、適合した構文は均等にシャッフルした袋から選びます。採点は合格圏を決める足切りとして使い、圏内では均等に抽選します。通常変換では利用可能な構文を一巡するまで直近の同一構文を避けます。テスト時はseedを指定して同じ選択を再現できます。

系列指定時は、出来事型に合う機能構文と系列構文を直交させて候補を作ります。3案を選ぶ際は内容側の機能構文だけでなく、系列構文のシグネチャも重複させません。このため、同じ入力を系列だけ切り替えた場合も、単なる単語差ではなく導入・根拠の積み方・結論の置き方が変わります。

## 完全文脈モード

完全ブロントナイズでは、原文の文順へ語尾を足す処理を行いません。段落から事実、役割、成果、数値、問題、予定を分離し、本人の自慢、知り合いのナイト、第三者の目撃、結果先行の回想、LSの噂、名言導入、悲嘆先行、証拠先行、後日談先行へ再配置します。各候補は段落全体との比較に加えて、救援・達成なら危機、介入、成果、反応、結論、状態なら観察、対比、耐性、結論、中立観察・評価なら導入、一般人との認識差、見切り、反応、結論が揃っているかを検証します。名言の個数だけでなく、導入、危機・対比、介入、反応、結論という機能カテゴリが三つ以上あることも要求します。

候補生成は次の独立した編集層を組み合わせます。

- 丁寧語と視点の変更
- 実ログから集計した半角カナ表記
- 段階比較から得た語彙差分
- 内容に対応する強調語や定型表現
- 実ログ検索結果に現れた導入、断定、比較の文型
- 行動と相手の反応を組み直す構造変換
- 有頂天レベルだけで行う補足結論の生成

通常は1文につき10件以上の候補を作ります。

完全モードでは25候補以上を作り、品質基準を通過した集合に対して、直近8回で使った名言パターンと直近6回の段落構造を除外条件として適用します。これは出現数による重み付けではなく、反復の少ない候補集合を作るための足切りです。その集合内では均等に抽選します。

## 検証と選択

各候補は次の値を持ちます。

### 意味保持

- 入力の内容語が候補内に残る割合
- 同義概念への置換として説明できる割合
- 肯定と否定の一致
- 数値、URL、メールアドレス、英字識別子の完全保持
- 入力に対する長さの増加率

### 文体

- 実ログn-gramへの近さ
- 長文改変n-gramへの近さ
- 入力文からどれだけ文体距離が改善したか
- 視点、表記、接続、断定、誇張、反応、階級比較の多様性
- 実ログ全体の特徴量分布への近さ
- 指定した倉庫系列内の実ログn-gramと特徴量分布への近さ
- 指定系列のTF-IDF重心とのコサインと、系列内実ログ文の上位3近傍コサイン。重心35%、近傍65%で全9系列を同時比較する

### 接続品質

- 括弧の対応
- 同じ表現の過剰反復
- 語尾の重複
- 異常に長い一文

変換レベルごとに意味保持と文体の重みを変えます。基準を満たし最高点に十分近い候補を合格帯とし、その帯では均等に抽選します。基準を満たさない場合は、意味保持を優先した候補を作り直して再検証します。

系列構文は内容を置き換える文ではなく、指定した系列ページで確認した談話上の外枠です。そのため長さの増加だけでは意味保持点を落としませんが、内容語、肯定・否定、数値などの保護値は通常候補と同じ基準で検査します。指定系列と異なる構文、複数系列の混在、系列構文の欠落は不合格です。

検証器の回帰テストには、生成処理を呼ばずに記述した9系列の固定正例を使います。また正例の一部を壊した別系列、意味反転、文脈違い、数値欠落の負例も同じ検証器へ通します。これにより、候補生成と検証が同じ誤りを共有して全件合格する自己確認を避けます。

## 画面での比較

各文について次を表示します。

- 入力文と採用文のトークン差分
- 総合、意味保持、実ログ近似、長文近似、指定系列コサイン、接続品質
- 比較した候補数と検証回数
- 参照した実ログ、入力とのコサイン類似度、投稿元
- 総合点上位の別候補

結果だけでなく選択過程を見せることで、誤変換を見つけて辞書や候補生成を修正できます。
